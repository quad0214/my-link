# 마이링크 마이페이지 링크 추가 PRD

## 1. 문서 목적

이 문서는 링크트리형 서비스 마이링크(MyLink)의 현재 시연 범위를 정의한다. 이번 단계에서는 `/mypage`에 프로필과 링크 목록을 표시하고, 사용자가 다이얼로그에서 새 링크를 추가해 현재 브라우저 세션에서 바로 확인할 수 있게 한다.

서버·데이터베이스와 연결하지 않으며 추가한 링크는 새로고침하면 초기 Mock 데이터로 돌아간다.

| 항목 | 내용 |
| --- | --- |
| 제품명 | 마이링크 (MyLink) |
| 현재 단계 | 마이페이지 링크 추가 |
| 대상 사용자 | 개인 사용자, 크리에이터 |
| 화면 경로 | `/mypage` |
| 초기 데이터 | `src/mocks/profile-links.json` |
| 상태 관리 | Zustand 메모리 상태 |
| UI 기반 | shadcn/ui |
| 스타일 | Tailwind CSS 4 |
| 디자인 기준 | 프로젝트 루트의 [`design.md`](../design.md) |

## 2. 제품 개요

마이링크는 개인과 크리에이터가 자신의 소개와 여러 외부 링크를 한 페이지에 모아 공유하는 서비스다.

최종 제품은 프로필 소유자가 링크를 구성하고 `/[username]` 공개 주소를 공유하는 형태를 목표로 한다. 현재 시연에서는 계정과 공개 페이지를 분리하지 않고 `/mypage` 하나에서 프로필 확인과 링크 추가 흐름을 검증한다.

## 3. 현재 단계의 목표

1. `/mypage`에 Mock 프로필, 섹션, 링크 목록을 표시한다.
2. 사용자가 `링크 추가` 버튼으로 다이얼로그를 열 수 있다.
3. 제목, URL, 설명을 입력해 링크를 추가한다.
4. 추가 결과를 기존 링크 카드와 같은 형태로 즉시 보여준다.
5. 서버나 LocalStorage 없이 Zustand 메모리 상태로만 동작한다.
6. 새로고침하면 Mock 데이터로 초기화된다.
7. 모바일부터 데스크톱까지 반응형과 접근성을 유지한다.

## 5. 사용자 시나리오

### 5.1 프로필 소유자의 링크 추가

**사전 조건:** 사용자가 `/mypage`에 접속했고 Mock 프로필과 링크가 표시되어 있다.

1. 사용자가 `링크 추가` 버튼을 선택한다.
2. 앱이 링크 추가 다이얼로그를 연다.
3. 사용자가 제목과 HTTP·HTTPS URL을 입력한다.
4. 필요하면 설명을 입력한다.
5. 사용자가 `추가하기`를 선택한다.
6. 앱이 입력을 검증하고 새 링크를 목록 마지막에 표시한다.
7. 앱이 성공 상태를 보조 기술에도 전달한다.

**기대 결과:** 사용자는 페이지를 벗어나지 않고 링크를 추가하고 실제 카드 형태로 확인할 수 있다.

### 5.2 현재 세션의 링크 확인

1. 사용자가 추가된 링크 카드의 아이콘, 제목, 설명을 확인한다.
2. 링크를 선택하면 새 탭에서 외부 URL이 열린다.
3. 사용자가 페이지를 새로고침한다.
4. 앱은 추가한 링크를 제거하고 초기 Mock 목록을 다시 표시한다.

**기대 결과:** 현재 단계가 서버 저장 전의 로컬 시연임을 사용자가 이해할 수 있다.

## 7. 기능 요구사항

### 7.1 초기 데이터

- `src/mocks/profile-links.json`을 정적으로 import한다.
- 서버 요청을 만들지 않는다.
- 섹션과 링크를 `sortOrder` 오름차순으로 표시한다.
- `visible`이 `false`인 블록은 표시하지 않는다.
- 알 수 없는 아이콘은 기본 링크 아이콘으로 대체한다.
- HTTP·HTTPS가 아닌 기존 링크는 표시하지 않는다.

### 7.2 링크 추가 다이얼로그

- shadcn/ui `Dialog`, `Input`, `Label`, `Button`을 사용한다.
- 열릴 때 제목 입력란으로 초점을 이동한다.
- `Esc`, 닫기 버튼, 배경 선택으로 닫을 수 있다.
- 제목과 URL은 필수이고 설명은 선택이다.
- 검증은 입력 중이나 포커스 이동 시 실행하지 않고 `추가하기` 제출 시점에만 실행한다.
- URL은 `http://` 또는 `https://` 프로토콜만 허용한다.
- 유효하지 않은 입력은 다이얼로그를 유지하고 해당 입력란에 붉은 테두리와 필드별 오류 메시지를 표시한다.
- 검증 오류가 하나라도 있으면 링크를 추가하지 않는다.
- 유효한 입력은 `LinkBlock`으로 변환해 목록 끝에 추가한다.
- 새 링크에는 기본 `globe` 아이콘을 사용한다.
- 성공하면 폼을 초기화하고 다이얼로그를 닫는다.

### 7.3 링크 카드

- 카드 전체를 클릭 가능한 외부 링크로 제공한다.
- 아이콘, 제목, 설명 또는 URL, 외부 이동 아이콘을 표시한다.
- 새 탭에서 열고 `noopener noreferrer`를 적용한다.
- 최소 터치 영역과 키보드 포커스 상태를 제공한다.

### 7.4 상태 수명

- Zustand 스토어는 Mock 데이터를 초기 상태로 사용한다.
- `addLink` 액션은 브라우저 메모리의 `blocks`만 변경한다.
- LocalStorage, SessionStorage, 쿠키를 사용하지 않는다.
- 새로고침하거나 새 세션을 시작하면 Mock 데이터로 초기화한다.

## 8. 데이터 모델

```ts
type LinkIcon = "instagram" | "youtube" | "globe" | "github";

type LinkBlock = {
  id: string;
  type: "link";
  title: string;
  description: string;
  url: string;
  icon: LinkIcon;
  visible: boolean;
  sortOrder: number;
};

type SectionBlock = {
  id: string;
  type: "section";
  title: string;
  visible: boolean;
  sortOrder: number;
};

type ProfileState = {
  profile: Profile;
  blocks: Array<SectionBlock | LinkBlock>;
  theme: "light" | "dark" | "system";
  addLink: (link: Pick<LinkBlock, "title" | "description" | "url">) => void;
};
```

새 링크의 `sortOrder`는 현재 가장 큰 값보다 1 크게 지정하고 ID는 브라우저에서 생성한다.

## 10. 디자인 요구사항

프로필과 링크 목록의 시각·행동 원칙은 [`design.md`](../design.md)를 기준으로 하고, 컴포넌트 구조와 접근성 기반은 shadcn/ui를 사용한다. 제품 화면에는 디자인 참고 대상의 명칭, 로고, 상표, 저작권 또는 출처 문구를 표시하지 않는다.

- 프로필과 링크를 한 열의 짧은 카드 흐름으로 구성한다.
- Compact(600px 미만)는 최소 24px 좌우 여백을 사용한다.
- Medium(600~839px)은 읽기 폭을 유지하며 여백을 확장한다.
- Expanded(840px 이상)는 콘텐츠를 적절한 최대 너비로 중앙 정렬한다.
- 버튼과 입력 요소는 최소 44px 수준의 편안한 터치 영역을 제공한다.
- 라이트·다크 테마에서 동일한 정보 위계를 유지한다.
- dim과 shadow를 같은 요소에 동시에 적용하지 않는다.

### 10.1 스타일 작성 규칙

- 화면과 제품 컴포넌트는 Tailwind CSS 유틸리티 클래스로 작성한다.
- CSS Module과 페이지 전용 전역 선택자는 사용하지 않는다.
- `src/app/globals.css`는 Tailwind·shadcn import, 디자인 토큰, 전역 base, 모션 감소 설정에만 사용한다.
- 조건부 클래스는 `cn()`으로 결합하고 반복 변형은 `cva`로 관리한다.

## 11. 접근성 요구사항

- 모든 입력에 명시적인 레이블을 연결한다.
- 다이얼로그에 제목과 설명을 제공한다.
- 다이얼로그가 열리면 내부로 초점을 이동하고 닫히면 트리거로 복원한다.
- 오류 메시지는 `role="alert"`로 전달한다.
- 추가 성공 메시지는 `aria-live="polite"`로 전달한다.
- 아이콘 전용 버튼에 한국어 접근성 이름을 제공한다.
- 장식 아이콘은 보조 기술에서 숨긴다.
- 키보드만으로 열기, 입력, 제출, 닫기가 가능해야 한다.
- 200% 확대와 최소 360px 너비에서 가로 스크롤이 없어야 한다.
- `prefers-reduced-motion`을 존중한다.
